## Visible feedback loop for every UX rollout

1. Capture the actual before view (or preserve the user's supplied capture) with its appearance and state. Keep synthetic examples separate from private calendar data.
2. Give UX the image and the exact complaint, then challenge the treatment through quick-glance reading, reduced contrast vision, keyboard use, first-time discovery and native macOS light/dark appearance.
3. Rank concrete problems and implement the smallest visible improvement. PM keeps delivered features, current work and proposals distinct.
4. Show the proposal clearly labeled, then obtain an actual after capture for the source being shipped. UX reviews the final image, not just code or a mockup.
5. QA checks regressions in its own chat. Release acceptance includes readable appearance, useful interactions and source identity; background test infrastructure does not count as a feature rollout.
